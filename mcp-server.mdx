# MCP Server

The Datafiniti MCP server lets any MCP-aware client — Claude, ChatGPT, Codex, or an agent framework — query Datafiniti's product, business, property, and people data directly. It's one of several ways to use Datafiniti with AI (see the [Overview](https://docs.datafiniti.co/overview)); this one is best when you want an assistant or agent to _run_ queries on its own rather than just help you write them.

Because the MCP server reuses the exact same request-handler functions the public API uses, MCP and REST behave identically. There's no second implementation to drift out of sync — a fix or feature on one surface applies to both.

## When to use MCP

Use the MCP server when:

- Your client supports MCP natively and you want it to execute searches and downloads without a human relaying results.
- You're building an agent that goes from a natural-language goal to a structured data pull in one flow.

If you'd rather have an assistant help you _build_ a query that you run yourself, you don't need MCP at all — see [Claude](https://docs.datafiniti.co/claude) or [Other LLMs](https://docs.datafiniti.co/other-llms).

## 1. Get your API token

The MCP server uses the same bearer token as REST — there's no separate MCP credential. Get your token from the [Datafiniti Web Portal](https://portal.datafiniti.co/settings/api), log in, and open settings from the left navigation bar. \

## 2. Point your client at the endpoint

The server is mounted at:

```typescript
https://api.datafiniti.co/v4/mcp
```

It uses the **Streamable HTTP** transport — a single HTTP endpoint that carries the `initialize` handshake, `tools/list`, `prompts/list`, and tool calls, plus an optional server-to-client stream.

## 3. Authenticate

The MCP server sits behind the same authentication as every other Datafiniti route, so you authenticate with a bearer token:

```typescript
Authorization: Bearer AAAXXXXXXXXXXXX
```

Your token tells the server who you are, what you have access to, and how to account for credits — exactly as it does for a REST call. Field permissions are enforced identically to REST.

**Handshake overlap**

A single MCP handshake legitimately issues several requests in quick succession — `initialize`, `notifications/initialized`, `tools/list`, `prompts/list`, and an optional stream request. This is expected and accounted for.

## 4. Available tools

Once connected, the client can list and call these tools. Each reuses the same REST request handler the public API uses, so behavior, permissions, and pricing match REST exactly.



| Tool                 | What it does                                     | Notes                                                                              |
| -------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `df_search`          | Search records matching a query                  | Returns up to 50 records per call; charges credits identically to REST `/search`   |
| `df_count`           | Count records matching a query                   | No records returned, no credit cost                                                |
| `df_start_download`  | Start an asynchronous download                   | Poll `df_download_status` for progress. Capped at 100,000 records at the MCP layer |
| `df_download_status` | Check the status of a download                   | Returns links to result files once complete                                        |
| `df_get_record`      | Retrieve a single record                         |                                                                                    |
| `df_get_schema`      | Fetch the field-name-to-type map for a data type | Returns the fields an agent needs to write a query                                 |

**Choosing a tool**

Use `df_count` to size a result set before spending credits, `df_search` for small or targeted pulls (up to 50 records), and `df_start_download` when a use case's scope implies many records.

## 5. Run a query

Call `df_search` with a query string and a record count. For a property search:

```typescript
{
  "query": "country:US AND propertyType:\"Single Family Dwelling\"",
  "num_records": 10
}
```

The server runs the same handler as REST `/search`, charges credits identically, and returns a response containing `num_found`, `total_cost`, and a `records` array — the same shape a REST search returns.

<Callout kind="tip" collapsed="false">
  **Escaped quotes**

  Exact-match values inside a query use escaped quotes — `propertyType:\"Single Family Dwelling\"` — not unescaped quotes.


</Callout>

### Query syntax

The server exposes Datafiniti's full query syntax to the client: boolean operators, negation, parentheses, nested-field dot notation, ranges, and the compound `{}` syntax for matching multiple sub-field requirements within a single nested object. See the per-data-type guides: [Property](https://docs.datafiniti.co/docs/constructing-property-queries), [People](https://docs.datafiniti.co/docs/constructing-people-queries), [Product](https://docs.datafiniti.co/docs/constructing-product-queries), and [Business](https://docs.datafiniti.co/docs/constructing-business-queries).

### Views

The `view` parameter on `df_search` and `df_start_download` controls which fields come back. A string names a default or saved view; an array is an ad-hoc view of `{"name": "<field>"}` objects, with nested sub-fields expressed as dot notation in the `name` (for example, `"descriptions.value"`).

### Defaults

`df_search`'s `sort` defaults to `dateUpdated` descending, and `fuzzy_match` defaults to `'on'` for address fuzzy-matching — both matching the REST `/search` endpoint's defaults exactly.

## 6. Prompts

The server ships a library of prompts, each converting a `docs.datafiniti.co` use-case guide into a ready-to-run query template. A prompt doesn't execute anything itself — it returns a built query and tells the client which tool to run next (`df_search` for a small, targeted result set, or `df_start_download` when the guide's scope implies many records).

Where a prompt argument has a small, verified value set (such as a property `status`), it's defined as an enum, so clients that render prompt forms show a dropdown instead of a free-text box. MCP prompt arguments are transmitted as a flat string-to-string map, so every argument is a simple string — nested values use dot notation.

The prompts available for each data type are listed on that data type's "…with AI" page.

## 7. Structured errors

The tools agents actually hit return a structured error object rather than a bare status code or loose string:

```typescript
{
  "code": "invalid_query",
  "message": "…",
  "field": "query"
}
```

Branch on the stable `code` — for example `invalid_query`, `invalid_view`, `out_of_range`, `credit_limit_exceeded`, or `no_results` — rather than string-matching the `message`.
