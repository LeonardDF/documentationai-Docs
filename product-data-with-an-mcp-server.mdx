# Product Data with an MCP Server

This guide walks through end-to-end examples of using the [MCP Server](https://docs.datafiniti.co/mcp-server) against **product data**. It assumes you've already connected a client and authenticated — see the [MCP Server](https://docs.datafiniti.co/mcp-server) guide for setup, transport, and the full tool reference.

Every example here uses the same tools (`df_count`, `df_search`, `df_start_download`, `df_download_status`) and the same query syntax as the other data types; what changes are the fields, nested sub-fields, and views specific to product records. For the underlying reference, see the [Product Data Schema](https://docs.datafiniti.co/docs/product-data-schema) and [Constructing Product Queries](https://docs.datafiniti.co/docs/constructing-product-queries).

## The goal

Say we want **Apple laptops**, with their pricing and descriptions — first to size the set, then to pull a sample, and finally to export descriptions and reviews for analysis.

## 1. Size the result set with `df_count`

Start with a count. It returns no records and costs no credits, so it's the cheapest way to confirm a query is scoped correctly before spending anything.

```typescript
{
  "query": "brand:Apple AND categories:laptops",
  "type": "product"
}
```

A response tells you how many records match:

```typescript
{
  "num_found": 742
}
```

<Callout kind="tip" collapsed="false">
  **Match multiple values in one field**

  Product queries frequently match several values in a single field. Group alternatives with parentheses — `categories:(laptops OR desktops)` — to widen the match without repeating the field.


</Callout>

## 2. Pull a targeted sample with `df_search`

Now retrieve a handful of records. `df_search` returns up to 50 per call and charges credits identically to REST `/search`.

```typescript
{
  "query": "brand:Apple AND categories:(laptops OR desktops)",
  "type": "product",
  "num_records": 5,
  "view": ["name", "brand", "categories", "prices.amount", "prices.currency"]
}
```

The response has the same shape as a REST search — `num_found`, `total_cost`, and a `records` array:

```typescript
{
  "num_found": 742,
  "total_cost": 5,
  "records": [
    {
      "name": "…",
      "brand": "Apple",
      "categories": ["laptops"],
      "prices": [
        {"amount": "000.00", "currency": "USD"}
      ]
    }
  ]
}
```

## 3. Work with nested sub-fields

Product data leans heavily on nested structures — prices, descriptions, and reviews are all nested objects. Reference their sub-fields with dot notation, both in queries and in views.

Query on a nested sub-field:

```typescript
{
  "query": "brand:Apple AND descriptions.value:\"Retina display\"",
  "type": "product"
}
```

Request nested sub-fields in a view with dot notation in the `name`:

```typescript
{
  "view": [
    {"name": "name"},
    {"name": "brand"},
    {"name": "descriptions.value"},
    {"name": "reviews.text"}
  ]
}
```

**Dot notation, not sub-field arrays**

Nested sub-fields are expressed as dot notation in a view's `name` — `"descriptions.value"` — rather than as a separate sub-fields array.

## 4. Use the compound `{}` syntax

To require multiple sub-fields to match _within the same nested object_ — rather than anywhere across separate objects — use the compound `{}` syntax. For example, to match a product that has a single price record that is both under a threshold and in USD:

```typescript
{
  "query": "brand:Apple AND prices:{amount:[* TO 1000] AND currency:USD}",
  "type": "product"
}
```

This differs from an unbraced `AND`, which would let the two conditions be satisfied by different price records on the same product. See [Constructing Product Queries](https://docs.datafiniti.co/docs/constructing-product-queries) for a full explanation.

## 5. Export descriptions or reviews with `df_start_download`

A common product use case is pulling descriptions or reviews in bulk — for analysis or for training a model. Start an asynchronous download, capped at 100,000 records at the MCP layer.

```typescript
{
  "query": "categories:laptops",
  "type": "product",
  "format": "JSON",
  "view": ["name", "brand", "descriptions.value", "reviews.text", "reviews.rating"]
}
```

This returns a download identifier. Poll it with `df_download_status`:

```typescript
{
  "download_id": "…"
}
```

Once the status comes back complete, the response includes links to the result files.

## 6. Run a product prompt

Prompts turn a product use-case guide into a ready-to-run query template. For example, `search_by_gtin` looks up a product by its GTIN, `lookup_product_by_brand_model` finds a product by brand and model number, and `export_llm_training_data` scopes a query to descriptions or reviews and — because the scope implies a large pull — routes the client to `df_start_download` rather than `df_search`.

For the full list of product prompts, see [Product Data with AI](https://docs.datafiniti.co/docs/product-data-with-ai).
